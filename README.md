# Overview:
- Goal: Students will design a testing plan for a given software/system, carry out tests, review results, and refine the plan—all using the PDCA cycle.

- Duration: 2 weeks (10 working days, e.g., Monday→Friday each week)

## Deliverables:

- Written testing plan (Plan)

- Execution of tests + log of test results (Do)

- Review/feedback session: findings, metrics, issues (Check)

- Revised testing plan/improvement actions (Act)

- Participants: Teams of students (you may decide team size)

## Activities:
#### Plan: Write the test plan:
- Teams draft the testing plan: objectives, scope, deliverables, schedule, resources, test environment, entry/exit criteria, metrics, risk assessment, test items, types of tests (functional, non-functional, regression etc.).

- Do: Set up environment, prepare test cases, execute tests and collect data: 
_Teams set up the test environment (hardware, software, data)._

- Create detailed test cases/scripts based on the test plan: inputs, expected results, pass/fail criteria.
Document logging mechanism for test results.
Teams execute the set of test cases.
Log results (pass/fail), record defects/issues, note any blocker or environment issues.

- At end this phase, each team submits a short status summary: 

* how many test cases executed, how many passed/failed, major issues.
Capture additional metrics (e.g., number of defects found, defect severity, time per test, environment anomalies).

- Check: Analyse test results, review progress:
Teams analyse results: defect trends, test coverage, pass/fail ratio, any stuck tests.

* Teams hold a “review meeting” (you observe or facilitate) and prepare a short presentation: what’s going well, what’s not, major risks, recommended changes.

_Instructor and teams discuss feedback._

- Act: Improve based on insights & revise plan:
Based on the Check phase, teams adjust their test plan: e.g., add new test cases, remove redundant ones, change priorities, improve environment setup, fix logging/reporting.
Also plan for “regression” re-run of failed test cases and any new ones.

- Do: Execute revised test plan (regression & new cases):
Teams run the revised plan: rerun failed tests, run new ones, capture metrics again.
Log results, document improvements compared to previous run.
Check & Act: Final review, feedback, wrap-up:
Teams present final results: metrics (initial vs revised), defect trends, coverage improvements, environment/test process improvements.
Instructor gives feedback, class discussion on lessons learned and how the PDCA cycle helped.
Teams submit 

* final report: updated test plan, test case log, defect log, improvement actions, reflections on the process.
Additional details & tips
Metrics to track: Number of test cases executed, pass/fail count, defect count (by severity), test execution time, % coverage of features, number of defects found per test case, etc. Helps with Check phase.
Reflection prompts: At the end of each major phase (Plan, Do, Check, Act) ask students: What went well? What didn’t go as planned? What would we change next time?

- Time allocation: Since it’s only two weeks, keep test scope moderate: maybe one major functional scenario + one non-functional test (e.g., performance or usability) to keep workload manageable.

- Team collaboration: Encourage use of version control (e.g., Git) for test artifacts, and perhaps a shared dashboard or spreadsheet for logging test run results.

- Reflection and continuous improvement: End with students listing 2-3 concrete improvements they would make next iteration or in a real project.

- Deliverables to grade:
Continuous improvement and PDCA cycle investigation, (previous activity)
Types of software tests investigation (previous activity)
Quality of test plan, (actual activity)
Execution and feedback document, 
Review and improvements document, 
Presentation/reflection
